01

Executive Summary (핵심 브리핑)

경영진 및 비개발자 요약

본 보고서는 ITDA OCR Challenge(식품 유통·소비기한 자동 추출) 과제에서 개발된 인공지능 파이프라인의 최고 성능 구조와 전체 실험 분석 결과를 다룹니다. 복잡한 수식 대신 "어떻게 글자를 찾고, 어떻게 진짜 소비기한을 고르는가"를 명확한 실측 수치와 함께 정리했습니다.

🏆 최고 성능 달성 구조
Full OCR + YOLO Dual-Branch Union
전체 사진을 넓게 보는 시야(Branch A)와 소비기한 영역만 정밀하게 확대하는 돋보기(Branch B)를 합친 이중화 앙상블 구조
📊 검증된 최고 실측 성능

02

문제 정의와 대회 실행 제약

엄격한 개발 규칙

실제 제품에 인쇄된 소비기한은 폰트가 규격화되어 있지 않고, 비닐의 구김, 조명 반사, 제조일자나 바코드와의 혼재 등 현실적인 방해 요소가 극심합니다. 본 대회는 현실 배포 환경을 상정하여 다음과 같은 엄격한 3대 제약 조건을 요구합니다.

1. CPU-Only (4-Core 타겟)
제출 및 최종 평가는 GPU가 없는 순수 4-core CPU 서버에서 수행됩니다. 모델 크기와 연산량이 작아야 하며, 메모리 누수가 없어야 합니다.
2. 완전한 오프라인 추론
추론 시 인터넷 연결, 외부 API 호출, 원격 대규모 언어모델(GPT-4, Gemini 등) 연동이 원천 금지됩니다. 로컬 경량 모델만 구동 가능합니다.
3. Test Split 철저 잠금
데이터 오염(Data Leakage)을 방지하기 위해 459장의 Test Split은 모델 튜닝에 절대 사용하지 않았으며, 오직 고정된 Validation(459장)으로만 검증했습니다.

결정적 발견:
Kaggle 데이터셋을 활용해 성능이 오른 이유는 "새로운 이미지가 추가되어서"가 아니라, 기존 사진 속 날짜 위치(date/due box) 좌표 라벨이 추가로 확보되어 정밀한 YOLO Detector를 학습시킬 수 있었기 때문입니다.

CPU 대회 환경 호환성 및 안정성 감사

실제 환경 배포 적합성 검증

대회 채점 서버는 순수 4-core CPU 오프라인 환경입니다. 모델이 아무리 정확해도 CPU 환경에서 런타임 에러가 나거나 1장당 수십 초가 걸리면 실격 처리됩니다. 다음 항목들을 정밀 점검했습니다:
